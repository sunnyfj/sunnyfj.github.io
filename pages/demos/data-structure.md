# 数据结构 与 算法

##  1. 数组（Array）：连续内存的性能怪兽
- 底层本质：在内存中开辟一块连续的空间，存储相同类型的数据。
- 核心特性： * 随机访问极快： 拥有严格的下标（Index）。查找任意位置的元素，其时间复杂度为 $O(1)$（因为可以通过 首地址 + 下标 * 元素大小 直接寻址）。
    - 插入/删除极慢： 移除或插入一个非末尾元素，需要将其后面的所有元素在内存中集体向前或向后平移，时间复杂度为 $O(N)$。
- 工程应用：适合高频读取、大小固定的线性数据集。

## 2. 链表（Linked List）：动态扩容的自由主义者
- 底层本质： 内存中不连续的空间。每个节点除了存储自身数据外，还包含一个指向下一个节点内存地址的指针（next）。
- 核心特性：
    - 插入/删除极快： 只要知道了目标位置，插入或删除只需要修改前后节点的指针指向即可，时间复杂度为 $O(1)$。
    - 查找极慢： 没有下标。想找某个元素，必须从头节点（Head）顺着指针一层层往后爬（遍历），时间复杂度为 $O(N)$。
- 工程应用： 现代响应式框架（如 React Fiber 架构的更新任务队列）、各种高级队列的底层实现。

## 3. 栈（Stack）与 队列（Queue）：严格的秩序守护者
这两个属于受限的线性表，人为限制了数据的存取规则，用于控制执行流。

- 栈（Stack）：后进先出（LIFO）
    - 规则： 只能在一端（栈顶）进行推入（Push）和弹出（Pop）操作。
    - 工程应用： 浏览器的历史记录前进后退、V8 引擎高频调用的函数调用栈（Call Stack）。

- 队列（Queue）：先进先出（FIFO）
    - 规则： 一端进（队尾 Push），另一端出（队头 Shift）。
    - 工程应用： JS 的事件循环宏任务队列（Event Loop Task Queue）、高并发中间件 RabbitMQ/Kafka。

## 4. 哈希表（Hash Table / Map）：$O(1)$ 查找的终极利器
- 底层本质： 通过一个“哈希函数”，把你的 Key（如字符串）转换成一个数字下标，然后直接对应到数组的内存位置。
- 核心特性：
    - 降维打击的性能： 无论是增、删、改、查，理想状态下的时间复杂度全部是严格的 $O(1)$。
    - 核心痛点： 哈希冲突（Collision）。不同的 Key 经过哈希计算可能会得到同一个下标，底层通常采用“链表法（拉链法）”或“开放寻址法”来解决冲突。
- 工程应用： 前端存储缓存、Redis 键值数据库、JavaScript 的 Map 和 Set 底层。

## 5. 树（Tree）：高维数据的检索中枢

最经典的是二叉树（Binary Tree），每个节点最多有两个子节点。而工程落地中最常用的是二叉搜索树（BST）与平衡树（如红黑树、B+树）。

- 核心特性：如果树是平衡的，查找、插入的时间复杂度可以被压低到 $O(\log N)$（即二分查找的效率，远快于线性 $O(N)$）。
- 工程应用： * 现代前端的 虚拟 DOM（Virtual DOM Tree） 树状结构。数据库的索引结构（MySQL 索引底层使用的 B+ 树，专门用来优化磁盘 I/O 高频查找）。

## 6. 图（Graph）：复杂网络关系的映射
- 底层本质： 由一组顶点（Vertex）和连接顶点的边（Edge）组成。分为有向图、无向图、带权图。
- 核心算法： 深度优先搜索（DFS）、广度优先搜索（BFS）、最短路径算法（Dijkstra）。
- 工程应用： * 社交网络（微信好友关系链、人脉推荐）。
    - 打包工具的依赖拓扑分析： Vite/Webpack 在打包时，会将各个文件模块（ESM）之间的 import 关系绘制成一张模块依赖图（Dependency Graph），据此完成代码的动态剪枝（Tree Shaking）与排序。

| 数据结构 | 随机查找时间 | 插入/删除时间 | 内存连续性 |
| --- | --- | --- | --- |
| 数组（Array） | O(1) | O(N) | 连续内存 |
| 链表（Linked List） | O(N) | O(1) | 离散内存 |
| 哈希表（Hash Map） | O(1) | O(1) | 连续 + 离散混合 |
| 平衡树（Tree） | O(log N) | O(log N) | 离散内存 |

## 7. 跳表（Skip List）：可以“二分查找”的链表
- 背景： 链表查找很慢（$O(N)$）。要想快，只能用平衡树（如红黑树），但红黑树在并发插入时需要频繁旋转，在高并发下锁的开销极大。
- 底层本质： 跳表在普通有序链表之上，建立了多层索引（类似于火车站的快车、慢车轨道）。
- 特性：
    - 查找、插入、删除的时间复杂度全部达到了 $O(\log N)$。
    - 工程优势： 实现起来比红黑树简单得多，且并发场景下更容易做锁分离或无锁（CAS）优化。
- 工程应用： Redis 的有序集合（ZSet） 底层核心结构。

## 8. 布隆过滤器（Bloom Filter）：空间利用率到极致的概率结构
底层本质： 一个非常长的 二进制位数组（Bit Array） 配合多个 哈希函数。

## 9. 前缀树 / 字典树（Trie Tree）：高效的字符串检索利器
底层本质： 一棵多叉树，用来保存大量的字符串。利用字符串的公共前缀来减少内存开销和查询时间。

## 10. 双向循环链表 + 哈希表 ➔ LRU Cache（复合结构）
- 背景： 打造一个高并发的本地缓存，需要满足：查找快（$O(1)$）、淘汰旧数据快（$O(1)$）。单靠任何一种结构都做不到。
- 底层本质： Map（哈希表）+ Double Linked List（双向链表） 的合体。
    - 哈希表负责提供 $O(1)$ 的精准定位能力。
    - 双向链表负责维持数据的访问时间先后顺序。一旦某个缓存被访问了，立刻将节点移到链表头部；当缓存满了，直接剔除链表尾部的节点。
- 工程应用： Vue 的 内置组件 `<KeepAlive>` 的组件缓存机制、V8 引擎内部的内存置换算法。

## 11. 堆 / 优先队列（Priority Queue）：动态找最值的利器
底层本质： 堆是一棵完全二叉树。大顶堆（每个节点都大于子节点，根节点最大）或小顶堆（根节点最小）。

## 总结
“在实际工程落地中，我们往往不再单独使用数组或链表，而是针对特定高并发场景，采用这些复合或变维的数据结构。比如高频范围查询我们看重 跳表 (Redis)，内存吃紧的无源去重我们上 布隆过滤器，而高频的状态/时间置换我们则用 哈希表 + 双向链表的 LRU 复合模型。”
