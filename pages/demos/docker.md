# docker

Docker 是一个开源的容器化平台。它将应用程序及其所有依赖（代码、运行环境、系统工具、库）打包到一个容器中。

Docker 的核心价值在于 “环境标准化”。它将应用及其依赖（库、配置、运行时）像乐高积木一样打包。

`Docker 基本操作流程`

- Build（构建）：
    - 开发者编写一个 Dockerfile（文本文件），定义系统镜像、安装包、拷贝代码和启动命令。
    - 执行 docker build 命令，将其转化为一个 Image (镜像)。

- Ship（运输）：将镜像推送到仓库（私有或公共）。
    - 将镜像推送到仓库（如 Docker Hub 或公司私有库）。
    - 这一步类似你把安装包传到云盘。

- Run（运行）：
    - 在服务器上执行 docker pull 拉取镜像。
    - 执行 docker run，镜像就会变成一个活的 Container (容器) 开始提供服务。

`Docker vs. 虚拟机 (VM)`

| 维度 | Docker (容器) | 虚拟机 (Virtual Machine) |
| :--- | :--- | :--- |
| **隔离级别** | **进程级隔离**。共享宿主机的 OS 内核，利用 Namespace 和 Cgroups 进行限制。 | **硬件级隔离**。通过 Hypervisor 虚拟出硬件，每个虚拟机都有完整的独立 OS。 |
| **启动速度** | **秒级**。像启动一个普通进程一样快。 | **分钟级**。需要经历完整的操作系统启动过程。 |
| **资源消耗** | **极低**。几乎没有额外开销，单机可运行成百上千个容器。 | **高**。每个实例都要预留内存、磁盘给 Guest OS，开销大。 |
| **镜像大小** | **MB 级**。通常只包含应用及其必要依赖。 | **GB 级**。包含完整的操作系统、库、内核等。 |
| **持续集成** | **天然适配 CI/CD**。环境高度一致，构建一次，到处运行。 | **较慢**。通常需要分发巨大的镜像文件，部署不够轻量。 |

`Docker 的场景`
- 微服务架构部署。
- 需要快速扩缩容。
- 开发、测试、生产环境需要严格一致。
- 在单台服务器上跑多个不同版本的后端服务（Node.js, Python, Go 等）。

`虚拟机 的场景`
- 需要运行完全不同内核的系统（如在 Linux 上跑 Windows）。
- 对隔离性有极端安全性要求（硬件级隔离更安全）。
- 需要完整的系统管理权限或内核定制。
